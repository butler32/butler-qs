# Оконный режим (тайлинг ⇄ окна)

Статус: в работе. Решения согласованы с владельцем конфига.

## Цель

Переключатель двух режимов:

- **Тайлинг** — обычный Hyprland с воркспейсами.
- **Оконный** — на каждом мониторе один воркспейс, все окна плавающие и переезжают на него. Окна можно мышкой перетаскивать между мониторами.

Положение окон запоминается отдельно для каждого режима и восстанавливается при возврате: воркспейс, монитор, позиция, размер (в тайлинге — доли разбиения), свёрнутость, fullscreen, закрепление, z-порядок.

## Принятые решения

1. Мониторы: **один оконный воркспейс на каждый монитор** — тот, что на нём активен при входе (workspace-rules не используются: после hot-plug воркспейсы могут жить не на тех мониторах, что в правилах). Перетаскивание окон между мониторами работает штатно; при возврате в тайлинг перетащенное окно считается новым для своего монитора.
2. Заголовки окон (hyprbars) — **пока нет**. Только рамка для ресайза (`general.resize_on_border`), snap, кнопки в доке и горячие клавиши.
3. Новое окно, открытое в оконном режиме, при переходе в тайлинг:
   1. воркспейс «по правилу» для приложения (`windows.lua`: code → 4 и т. д.);
   2. воркспейс окон того же класса на этом мониторе;
   3. воркспейс, активный на мониторе в момент входа в оконный режим.
4. Новое окно, открытое в тайлинге, при переходе в оконный: геометрия из памяти по классу (`classMemory`), иначе 60% рабочей области каскадом.
5. Свёрнутые окна при смене режима **разворачиваются**.
6. В оконном режиме **шорткаты смены воркспейсов блокируются** (SUPER+N, SUPER+SHIFT+N, колесо, жесты свайпа, special workspace). Блокировка делается в Lua-конфиге по флагу режима, а не удалением биндов.

## Архитектура

```
QS: services/WinMode.qml (singleton, владелец состояния)
 ├─ mode: "tiling" | "windowed"  (Config.windowing.mode)
 ├─ снимки: <state>/winmode.json  { tiling:{addr→rec}, windowed:{addr→rec}, classMemory:{class→geom} }
 ├─ слушает Hyprland.rawEvent / toplevels, ведёт живой снимок (debounce)
 └─ команды в Hyprland: Hyprland.dispatch(...) и hyprctl eval

Hyprland: scripts/hypr/winmode.lua → подключается последним в hyprland.lua
 ├─ именованное правило winmode-float (enabled=false): match class=".*", float, workspace="unset"
 ├─ глобальный флаг режима + обёртки для биндов смены воркспейсов
 └─ general.resize_on_border / extend_border_grab_area / snap.enabled
```

Состояние живёт в QS: Lua-состояние Hyprland теряется при `reload` (событие `config.unload`). После `configreloaded` QS заново применяет режим.

`rec` окна: class, title, monitor, workspace, floating, at, size, fullscreen (internal/client), maximized, pinned, minimized, order (focusHistoryID), group.

## Алгоритм

**Тайлинг → оконный**
1. Снимок `hyprctl clients -j` → `tiling`.
2. Включить `winmode-float`, поднять флаг блокировки воркспейсов.
3. Каждое окно: `float set` → `move workspace follow=false` (оконный воркспейс его монитора) → `move x,y` / `resize x,y` (из `windowed`/`classMemory`, иначе из тайлинга, иначе каскад).
4. Вернуть z-порядок, fullscreen, фокус. Свёрнутые развернуть.
5. UI: скрыть `Workspaces`, показать нижний док.

**Оконный → тайлинг**
1. Снимок → `windowed`, обновить `classMemory`.
2. Выключить `winmode-float`, снять блокировку.
3. По каждому воркспейсу из `tiling`: перенести окна в сохранённом порядке (слева направо, сверху вниз), `float unset`, затем двумя проходами выставить размеры (`resize relative=false`), допуск ±2 px.
4. Окна без записи — по политике (решение 3). Уведомление «N новых окон разложены».
5. Вернуть активные воркспейсы и фокус.

Риск: в dwindle размеры задаются деревом разбиений. Если точность недостаточна, запасной вариант — Lua-раскладка (`hl.layout.register`) с точной расстановкой по сохранённым долям.

## UI

- `components/WinModeToggle.qml` — виджет-переключатель в баре (регистрация по правилам CLAUDE.md).
- `Workspaces` скрывается через `wanted: WinMode.mode === "tiling"`.
- `components/WindowDock.qml` — нижняя панель на каждый экран (`LazyLoader`, `exclusiveZone`): иконки окон с группировкой, индикаторы, клик = фокус/развернуть, правый клик = меню (свернуть, на весь экран, закрыть), эффект «увеличения» как в macOS (гауссиан по расстоянию до курсора: `maxScale`, `radius`, `iconSize`), автоскрытие при fullscreen. Данные — plain-снимки из `Hyprland.toplevels`.
- Конфиг `Config.windowing` + страница Меню → Конфигурация → «Окна» + ключи `cfg.windowing.*` / `winmode.*` в ru и en + токены дока в `ThemeDef`.
- IPC: `qs -c butler ipc call winmode toggle|tiling|windowed|get|minimize|maximize|close`; bind в `keybindings.lua` через `unless_dota(...)`.

## Спайки (что проверить до реализации)

1. Возвращает ли `resize relative=false` на тайловых окнах dwindle исходные доли, и с какой точностью.
2. Перекрывает ли `winmode-float` с `workspace="unset"` правила `workspace="4"` и т. п. (порядок правил).
3. Ловится ли rawEvent `minimized` от `Toplevel.minimized=true` и от кнопок внутри приложений; не ломает ли фокус перенос в `special:minimized`.
4. Синтаксис `hyprctl eval` для `set_enabled` и повторного применения режима после `configreloaded`.
5. Как заблокировать workspace-бинды по флагу (обёртка-функция в `hl.bind`) и жесты.

### Результаты спайков

Проверено на живом Hyprland 0.56.2 (3 тестовых kitty на пустом воркспейсе):

1. **Размеры в dwindle — ОК.** Цепочка `float set` → `move workspace` → (другой воркспейс и обратно) → `float unset` по окну в порядке (x, y) пересобирает дерево, а затем `resize x,y relative=false` с одним проходом возвращает геометрию **точно** (совпали позиции и размеры всех трёх окон при неравных долях). Lua-раскладка не нужна; для сложных деревьев всё равно делаем второй проход и сверку.
2. **Порядок правил — ОК.** Именованное правило, созданное с `enabled=false` и позже включённое `set_enabled(true)`, с `float=true, workspace="unset"` перебивает более раннее `workspace="8 silent"` (окно открылось плавающим на активном воркспейсе). Правила `windows.lua` менять не нужно, достаточно создать правило после них.
3. **Сворачивание — ОК.** `move({workspace="special:minimized", follow=false})` убирает окно с экрана без смены воркспейса и фокуса; `workspace.id` становится отрицательным (−98), по нему док определяет «свёрнуто». Обратный `move` возвращает окно. Реакция на rawEvent `minimized` от `Toplevel.minimized` проверяется на этапе 6.
4. **`hyprctl eval`** выполняет произвольный Lua, **значения не возвращает** (печатает `ok`), глобальные переменные живут между вызовами (`WM_TEST:set_enabled(...)` работает). Чтение состояния — через `hyprctl clients -j`.
5. **Блокировка воркспейсов:** `Keybind:set_enabled` существует, но надёжнее глобальный флаг `WM_LOCK`: workspace-бинды оборачиваются функцией `ws_guard(dispatcher)` из `winmode.lua`, которая ничего не делает при `WM_LOCK`. Флаг теряется при reload, QS ставит его заново по `configreloaded`.

## Установка на новой машине

```
scripts/install-deps.sh --optional        # в т.ч. meson/ninja для заголовков окон
scripts/winmode/install.sh [--bars]       # без sudo, идемпотентно; --dry-run показывает шаги
hyprctl reload
qs -c butler ipc call winmode toggle      # или кнопка в баре
```

Скрипт: симлинк `configs/winmode.lua`, `require("configs.winmode")` последним в `hyprland.lua`, `WM_GUARD(...)` вокруг привязок смены воркспейсов в `keybindings.lua` (`patch-keybindings.js`; бинды с таблицей опций пропускает и сообщает номера строк — оберните вручную). Копии изменённых файлов — в `<state>/winmode-backups/`. `--bars` собирает hyprbars (`scripts/hyprbars/build.sh`); после обновления Hyprland повторите. `--uninstall` откатывает конфиг (плагин и состояние остаются). Виджет кнопки включается в Меню → Конфигурация → Виджеты бара.

### Дополнения после реализации

- dwindle сажает окно по позиции курсора, поэтому при возврате в тайлинг сторона задаётся явно: фокус на соседа из снимка + `hl.dsp.layout("preselect r|l|u|d")` + `float unset` (без этого окна двух-оконных воркспейсов менялись местами).
- Свёрнутые окна запоминают воркспейс в `minOrigin` (поэтому после `unminimize` возвращаются на свой воркспейс).

### Заголовки окон (hyprbars): стили macOS и Windows

- Плагин hyprbars + локальный патч `scripts/hyprbars/butler-buttons.patch` (плоские кнопки заданной ширины и цвет при наведении: `width`, `hover_color` в `add_button`). Сборка: `scripts/hyprbars/build.sh` (тег `hyprland-plugins` по версии Hyprland, `.so` в `~/.local/share/butler/hyprbars/`; после обновления Hyprland собрать заново).
- Стили описаны в `scripts/hypr/winframe.lua`: **mac** (светлая полоса 28 px, кружки красный/жёлтый/зелёный слева, значки при наведении, заголовок по центру) и **windows** (тёмная полоса 32 px, кнопки 46 px справа: свернуть, развернуть, закрыть; закрыть краснеет). Выбор — Меню → Конфигурация → Оконный режим → «Заголовки окон», хранится в `Config.windowing.frameStyle` и записывается в `<state>/winmode.style`.
- Заголовки видны только в оконном режиме: именованное правило `winmode-nobar` (`hyprbars:no_bar`) включено в тайлинге и снимается в `WM_SET(true)`.
- **Плагин грузит Quickshell** (`hyprctl plugin load` + `hyprctl reload`), а не конфиг: `hl.plugin.load` внутри конфига вызывает reload, reload выгружает плагин, и получается бесконечный цикл (12 тысяч перезагрузок за 10 секунд). Это и стало причиной OOM 2026-11-03, когда в тестовом конфиге вдобавок был `exec_cmd` с запуском терминалов.
- Проверка только во вложенном Hyprland под сторожем по памяти и числу процессов (`safe_nested.sh`, без `exec_cmd`). В основной сеанс плагин не загружался.
